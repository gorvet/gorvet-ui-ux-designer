# UX Research & Testing

Use this skill when uncertainty about users/tasks is material enough that design should not be based only on assumptions.

## Keep research proportional

Do not turn every UI task into a research project. Use lightweight evidence appropriate to decision risk.

## Discovery

Define the decision to inform, target participants, current behavior/context, assumptions to test, and what evidence would change the design.

Avoid leading questions. Ask about real past behavior before hypothetical preference.

## Usability testing

- Test realistic tasks, not “do you like this design?”
- Give users a goal without revealing the intended controls/path.
- Observe success, hesitation, wrong turns, recovery and interpretation.
- Separate severity/frequency from personal taste.
- Include accessibility-relevant participants/technology when the flow is critical and resources allow.

## Synthesis

Report evidence → impact → recommendation. Distinguish observed findings from inference. Do not manufacture quantitative certainty from small qualitative samples.

This skill informs the Design stage but is optional; it should not block implementation when the user already has sufficient requirements/evidence.
